Components · Form · 06 Textarea

Paragraphs with counts. Never single words.

Textarea is multi-line free text — Notes, context, P2 depth. It composes the TextInput skin (requires text-input.css) with auto height and a visible count; single values are TextInput, structured lines are rows of inputs, rich text is a different component.

  • 01

    Compose, never duplicate. textarea.field__input takes auto height, 88px min, spacing.3 pad, relaxed leading, vertical-only resize — the full TextInput state table rides along for free.

    Reject: redeclared error or focus states here, or horizontal resize breaking layout.

  • 02

    Min-heights set the depth. Base 88px, --sm 64px (spacing.16), --lg 160px; outlined, filled, error, success, disabled, and readonly are all inherited modifiers, never new states.

    Reject: a one-word textarea, or resize disabled entirely — small screens need it.

  • 03

    The count warns before the wall. .textarea__count sits right-aligned, xs muted; --limit flips it to role.warning-strong near the cap, with a sensible rows + maxlength and polite live announcements past 90%.

    Reject: a silent maxlength — the cap must always be visible.

Snippet — the contract in code

<label class="field__label" for="notes">Notes</label> <div class="textarea"><textarea id="notes" class="field__input" rows="4" maxlength="500" aria-describedby="notes-count"></textarea><span id="notes-count" class="textarea__count" aria-live="polite">0 / 500</span></div>
Do

Set sensible rows plus maxlength with a visible count. Keep vertical-only resize. Describe by help, error, and count ids together.

Don't

Never use textarea for one word. Never disable resize entirely. Never duplicate input states here.

Accessibility — the non-negotiables

Label + aria-describedby covering help, error, and count · error path identical to TextInput · count needs aria-live="polite" past 90% · touch height far exceeded · reduced-motion still.
