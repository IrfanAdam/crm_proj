Components · Identity · 06 Icon

Phosphor only. Decorative until named.

Icon is the Phosphor-only glyph system — registry plus CDN, currentColor, token sizes. Regular 1.5px stroke by default; fill weight marks selected. Legacy sprite.svg is fallback only; new work never touches it.

  • 01

    Anatomy — .icon frame · Phosphor svg at 100% · size modifier. The frame inherits context color; the svg fills it edge to edge. Five sizes, xs 12px to xl 32px; md 20px is the base with no modifier.

    Reject: any glyph outside the Phosphor registry — one foundry only.

  • 02

    Weight means state. Regular is default; fill marks selected or emphasis; bold is high-emphasis only. Selected state is fill weight plus signal color, applied via Icon.jsx — never a hand-swapped svg.

    Reject: fill weight as decoration — fill always answers selection.

  • 03

    Static — it inherits, never owns state. No hover, active, or disabled of its own; the surrounding control owns interaction. Muted and subtle inks exist for hierarchy, not for meaning.

    Reject: an off-scale size — xs–xl or nothing.

Snippet — the contract in code

<span class="icon icon--sm" aria-hidden="true"><!-- Phosphor svg --></span> <button aria-label="Close dialog"><span class="icon" aria-hidden="true"><!-- Phosphor svg --></span></button>
Do

Use Phosphor only via the registry. Mark decorative icons aria-hidden. Reserve fill for selected state. Name semantic icons through their control or role img.

Don't

Never use sprite.svg in new work. Never carry meaning by color alone. Never invent off-scale sizes. Never leave a semantic icon unnamed.

Accessibility — the non-negotiables

Decorative icons: aria-hidden="true", never focusable · semantic icons: exposed via the control's accessible name (e.g. button aria-label) or standalone role="img" + aria-label · icon color never carries meaning alone — contrast follows the surrounding text pair.
