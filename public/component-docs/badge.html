Components · Identity · 03 Badge

Counts beside things. Never things themselves.

Badge is the unread/count glyph beside a label or anchored to an object — an inbox total, a row count, a dot of presence. It annotates; it never acts, never filters, never carries meaning alone.

  • 01

    Anatomy — pill · bold micro count · tinted fill. Tinted fill with darker ink and a matching border, or a bare 8px .badge--dot with no text. Counts cap at 99+ via .badge--max with tabular numerals so the pill never wraps.

    Reject: an exact 4-digit count — cap it, never let the pill grow.

  • 02

    Static only — never interactive. No hover, active, disabled, or focus. A badge inherits its context's state (the button or row around it); giving it hover would promise an action it must not own. Keyboard users reach the anchor, never the badge.

    Reject: a focusable or clickable badge — the anchor owns interaction.

  • 03

    Overlap draws its own ring. .badge-wrap (relative anchor) + .badge--overlap pins the pill top-right with translate(50%,-50%); the pill's own border is the separation ring, so no extra halo token exists.

    Reject: a sixth tone — map every count to the five.

Snippet — the contract in code

<span class="badge badge--max">99+</span> <span class="badge-wrap"><span class="badge badge--overlap badge--dot" aria-hidden="true"></span></span>
Do

Pair every badge with a visible label or anchored object. Cap at 99+. Use the dot for presence only. Use overlap for icon and avatar anchors.

Don't

Never write a status word as a badge. Never make one focusable. Never invent a sixth tone. Never show an exact 4-digit count.

Accessibility — the non-negotiables

Redundant badge (label already states the count) is aria-hidden="true" · standalone badge (count unclear from context) gets aria-label (e.g. aria-label="5 unread") · dot always needs a text twin elsewhere · tint + dark ink keeps micro type readable · forced-colors keeps the count without hue.
