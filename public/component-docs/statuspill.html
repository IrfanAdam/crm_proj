Components · Identity · 04 StatusPill

Stage flags. Never color alone.

StatusPill is the record stage flag — Accepted, In Progress, Review, New, Warning, Danger. Solid fill, uppercase label, optional icon or dot. The label carries meaning in every state; hue never works solo.

  • 01

    Anatomy — pill · optional prefix · uppercase micro label. Optional leading status-pill__icon (Phosphor, icon-size-xs) or status-pill__dot (currentColor) for scan speed, then the uppercase label. Six tones, fixed ramp steps.

    Reject: a status told by hue alone — label (and prefix) always present.

  • 02

    Static by default — hover only when clickable. Plain pills have no hover. status-pill--clickable adds pointer + opacity-subtle hover; focus draws the 2px sapphire ring; disabled dims with no pointer.

    Reject: hover on a non-clickable pill — motion must not promise action.

  • 03

    Six hues, closed set. Accepted green, progress sapphire, review sapphire wash, new neutral-dark, warning orange, danger red. New stages map to the six; counts go to Badge, filters go to Chip.

    Reject: a seventh status hue — map, never invent.

Snippet — the contract in code

<span class="status-pill status-pill--progress"><span class="status-pill__dot" aria-hidden="true"></span>In progress</span> <button class="status-pill status-pill--review status-pill--clickable">Review</button>
Do

Always show the label. Use the icon or dot prefix when scanning speed matters. Reserve hover for clickable pills. Make clickable pills native buttons or links.

Don't

Never invent status hues. Never count with a pill. Never filter with a pill. Never leave meaning to color alone.

Accessibility — the non-negotiables

Status never color-alone (label + tone + optional prefix) · ink pairs gated AA · clickable pills are native <button> / <a> with the label as the accessible name · decorative prefix icons carry aria-hidden="true" · visible focus ring.
