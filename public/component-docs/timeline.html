Components · Data · 04 Timeline

Events on a spine. Done versus todo.

Timeline is the event spine: dots on a rail, hollow for todo and filled for done. It orders history; it never decorates chrome. Use it when time order explains; use ListRow when rows navigate.

  • 01

    Anatomy — rail · item · dot · label. Rail drawn in ::before, __item rows, __dot hollow until done, __label with right-aligned __time.

    Reject: a rail without dots — the spine never runs bare.

  • 02

    Three tones, no more. Status dots use green, orange, red 500 rings with matching done fills; default done is sapphire. DOM order always equals time order, even horizontal.

    Reject: a fourth dot hue — three status tones cover every event.

  • 03

    Geometry stays pixel-identical. 10px dot/rail geometry and the 6px dot offset sit off-scale and are kept as-is — no spacing token fits them.

    Reject: token-snapped dots — the spine geometry is exempt by decision.

Snippet — the contract in code

Do

Right-align times. Pair status dots with text. Keep DOM order equal to time order on the horizontal axis.

Don't

Never run the rail without dots. Never invent new dot hues. Never let done be dot-alone where status matters.

Accessibility — the non-negotiables

List semantics via role=list and items · done state needs text, not dot-alone, where status matters · horizontal variant keeps DOM order as time order · times right-aligned and plain.
