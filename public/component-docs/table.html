Components · Data · 01 Table

Comparable rows. One sorted column.

Table is the Opps ledger: sortable columns over comparable rows, keyboard-driven. It sorts and selects; it never hosts row actions inside the sort header. Use it when columns compare; use ListRow when rows navigate.

  • 01

    Anatomy — wrap · head · rows · footer. .table__wrap scroll container holds table.table; header cells sort, body rows carry data, .table__footer hosts the Pagination slot (count left, controls right).

    Reject: a sticky header scoped to the page — sticky lives inside .table__wrap only.

  • 02

    Density is a choice, not a drift. Default operates comfortable; table--compact goes dense Carbon-style; table--comfortable goes roomy for monitors. Striping is allowed only outside dense tables.

    Reject: striped dense rows — hover wash is enough signal at density.

  • 03

    Sort is announced, selection is railed. One sorted column at a time via aria-sort plus the sapphire arrow; .table__row--selected pairs the active wash with a sapphire inset rail.

    Reject: selection by fill alone — the rail must mark the picked row.

Snippet — the contract in code

<div class="table__wrap"><table class="table table--sticky"><th scope="col" aria-sort="ascending">Value</th><tr class="table__row--selected"><td class="table__cell--select"><input type="checkbox"></td></tr></table><div class="table__footer">…</div></div>
Do

Keep one sorted column at a time. Scope sticky to the wrap. Give selectable rows a leading checkbox column with scope and row aria-selected.

Don't

Never stripe dense tables. Never put actions inside the sort header. Never make the skeleton focusable.

Accessibility — the non-negotiables

Header cells carry scope=col · aria-sort ascending/descending with Enter/Space toggling and an audible announcement · checkbox column needs scope plus row aria-selected · empty state is a real row · skeleton is aria-busy, never focusable.
