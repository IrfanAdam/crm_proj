Components · Navigation · 03 Pagination

Position in a list. Never a wall of numbers.

Pagination moves through long lists — deals, activities, results. It pages and announces place; it never hides how much remains. Use full paging for tables; use compact prev/next where the slot is narrow.

  • 01

    Anatomy — nav · pages · status. nav aria-label="Pagination" holds first/prev, numbered .pagination__btn, next/last, plus .pagination__ellipsis and .pagination__status ("1–20 of 96"). The current page carries aria-current="page".

    Reject: numbers without a status line — every control answers "where am I".

  • 02

    Ellipsis compresses, compact strips. Distant ranges collapse to one …; .pagination--compact drops numbers for a joined prev/next strip. Both keep the status text — compression never deletes orientation.

    Reject: a compact strip with no status — fewer buttons means the words matter more.

  • 03

    Disabled, never vanished. Unavailable nav keeps its slot with disabled + --opacity-disabled so layout holds and intent stays legible. The active page is action-ink, not a link away.

    Reject: hiding prev on page one — ends disable, they never disappear.

Snippet — the contract in code

<nav class="pagination" aria-label="Pagination"> <button class="pagination__btn pagination__btn--active" aria-current="page">1</button> <span class="pagination__ellipsis" aria-hidden="true">…</span> <span class="pagination__status">1–20 of 96</span></nav>
Do

Pair every control with a status line. Keep end buttons disabled in place. Announce the current page.

Don't

Never link the current page. Never hide ends. Never drop the status in compact mode.

Accessibility — the non-negotiables

Landmark nav · aria-current="page" on the current button · disabled (not hidden) nav ends · announced status text · visible focus ring.
