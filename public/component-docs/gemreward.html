Components · Ceremony · 05 GemReward

One gem, four moods. Never in Operate.

GemReward is the achievement ceremony: one procedural gem canvas recolored per category from a token, standing on a capsule with Rock Solid Goals copy. Celebration only — quarantined from Operate and Monitor.

  • 01

    Anatomy — gem canvas · title · capsule · copy. One __spline gem canvas (data-gem = sapphire | citrine | amethyst | redberyl) drawn by the gem3d.js three.js scene from the portable gem-cut.js math, plus __title, __capsule stand (+Rs 4lakh · Beyond Target), __copy slots. One canvas, never four.

    Reject: a second gem canvas per category — switch the token, don't re-render.

  • 02

    Ceremony-only quarantine. Gems appear in achievement moments; mood never enters Operate/Monitor chrome, KPI fills, or measure visuals.

    Reject: a gem beside a KPI or inside Operate — ceremony leaking into chrome.

  • 03

    Token color API, reduced-motion exit. Category maps to a gem token: sapphire --primitive-sapphire-ui, citrine --primitive-citrine, amethyst --primitive-amethyst, red beryl --primitive-red-beryl. No filter pass, so the canvas keeps the token color exact. Reduced-motion drops to one still frame.

    Reject: a CSS filter or a second render to recolor the gem — the token is the paint.

Do

Use one gem canvas with the token map. Render the cut once and recolor by token. Keep mood quarantined.

Don't

Never place gems in Operate/Monitor. Never use gem hues as chrome. Never skip the reduced-motion still frame. Never render a second canvas per category.

Accessibility — the non-negotiables

Gem canvas is decorative · category meaning stays in real text (__capsule) · reduced-motion holds a still frame · copy stays real text.
