Components · Navigation · 04 Accordion

Stacked detail on demand. Never hidden chrome.

Accordion expands sections in place — record detail blocks, grouped filters, help text. It reveals and collapses; it never navigates. Use single-expand for exclusive sections, multi-expand for independent ones.

  • 01

    Anatomy — trigger · icon · panel. .accordion__trigger carries aria-expanded + aria-controls; .accordion__panel is hidden when shut. The chevron .accordion__icon trails by default, leads under .accordion--chevron-leading via order: -1.

    Reject: a panel with no labelled trigger — every region answers to its header.

  • 02

    Single or multi, same CSS. Single-expand closes siblings in JS; multi-expand leaves items independent. The mode is behaviour, never a second stylesheet — chrome stays identical either way.

    Reject: two accordion skins for two modes — behaviour varies, chrome does not.

  • 03

    Motion earns its keep. Panels animate grid-template-rows 0fr ↔ 1fr over --motion-duration-md; chevrons rotate 180°. Under prefers-reduced-motion transitions die and hidden toggles instantly.

    Reject: pixel-height keyframes or motion that survives reduced-motion — snap, don't slide.

Snippet — the contract in code

<div class="accordion__item"> <button class="accordion__trigger" aria-expanded="false" aria-controls="p1">Terms <span class="accordion__icon">›</span></button> <div class="accordion__panel" id="p1" hidden><div class="accordion__panel-inner">…</div></div></div>
Do

Wire aria-expanded to the panel's hidden state. Animate grid rows, not pixel heights. Snap instantly under reduced motion.

Don't

Never restyle per expand mode. Never leave disabled triggers reachable. Never animate raw height.

Accessibility — the non-negotiables

aria-expanded/aria-controls on triggers · instant hidden toggle · visible focus ring · disabled triggers skipped · no motion dependence.
