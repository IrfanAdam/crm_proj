# Mechanics Atlas — scheme-level canvas per lens

- Context: Atlas SVG shipped as single-column L1 essence (elbow paths, ~44 nodes, 4 lenses `logic/components/ia/truth`, deterministic stack `x=40, y=32+i*64`). Product scheme needs connector density: decisions × schema × logic (machines/states/rules/temporal), schema entities × fields × gem categories × Operate/Monitor flows, logic `NEXT` chain + transient vs temporal. Single-column elbows collapse at this density; mechanics engine provides pan/zoom/drag/highway routing.

- Options: (a) keep SVG — rejected: no corridor guards, no lane highways, no 0.18–3.8× gentle scaling (`p=0.38`), token-matched kind dots; (b) hand-place SVG overlaps — rejected: fragile at 40+ edges per lens; (c) port Tapmania `src/js/mechanics` canvas engine (8 modules, `route/corridor/render/popover/text`) verbatim — chosen; (d) 4th `truth` lens as canvas — rejected: layer truth is textual, stays in `docs/graph.mmd` + `gallery.html`, canvas is 3 product lenses only.

- Decision: replace `#atlas-canvas` SVG with `src/js/mechanics/` canvas (`canvas.js` + `canvas-interaction.js` + `render.js` 179-line waived per 007 + `route.js` highway `lane=max(G.y+h)+22+(idx%4)*14` + `corridor.js` guards + `popover.js` + `text.js` `p=0.38`), 3 lenses `decisions|schema|logic` (not 4) via `GRAPH_STORE` in `graph.js` (`localStorage mechanics:mode`, `CustomEvent('mechanics:mode')`), deterministic→highway routing (corridor-filtered `getRoute`, cost `hit*400+bends*12+len*0.05`, obstacles from every NODES+foreign GROUPS, highway spread), token shim DTCG (`tokens/mechanics-compat.json` → `design-system/tokens.css`; `stone→neutral-light/dark`, `violet→amethyst`, `amber→citrine`, `emerald→green`, `rose→red-beryl`, `blue-600→sapphire-ui-500`, `color-bg→bg-primary`, `z-mechanics→z-index-modal`, `size-tooltip:280px`).

- Why: scheme-level interconnectedness (not code detail, not presentation — `src/components/*`, `src/device/*`, `src/os/*`, `src/glass/*` remain presentation-only in `docs/graph.mmd`) requires the same engine so interaction is identical per tab but content is lens-optimal; `GROUP_BY_FILE` + per-lens `CORE` + `graphData.{decisions,schema,logic}.js` (generated, header `@generated`) are the single source; highway+corridor routing is the only proven way to keep 40+ edges legible without manual placement.

- Consequences: `src/arch/atlas.js` is orchestrator (`lens nav → engine.setMode()`), `atlas-state.js` validates `['decisions','schema','logic']` (default `logic`), `atlas-viewport/layout/render` retired; `scripts/generate-mechanics-graph.js` with `gen:mechanics`/`verify:mechanics` (Vite `mechanicsGraphPlugin` 150ms debounce) keeps graphs fresh; `verify:mechanics --check` fails on source touch until `gen:mechanics`; stale nodes dim `.52` + `amber-100` badge (render handles `n.stale`); `H`/`Esc`/arrow nav/`prefers-reduced-motion`/DPR cap 2 preserved; `ARCHITECTURE.md` layer map includes `src/js/mechanics/` and canvas contracts.
