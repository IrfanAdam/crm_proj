# Museum Refactor — Layered Prototype Architecture

**Goal:** Refactor the ALPHA CRM prototype into self-contained layers (shell / device / OS / glass / patterns / logic) without breaking anything, so a new developer or agent can build the whole product from this codebase alone.

**Architecture:** Extract-only refactoring — move code into layer-owned modules behind documented contracts, dedupe DS漂移, add unit tests + flow diagrams for the logic layer, and prove each phase with the existing gates (`npm test`, `vite build`, :5174 checks). No rewrites, no behavior change per phase.

**Tech Stack:** Vite MPA, vanilla JS + React islands, Leaflet, `@samasante/liquid-glass`, DTCG tokens.

**Tags:** Tooling, Layout, Component, Design System, Function, Motion

---

## Audit — where the layers stand today

Three questions, three answers (evidence below):

- **Presentation layer separate? No.** `index.html` (99 lines, at budget ceiling) mixes workspace shell, device markup, and 5 script tags; `app.css` mixes shell tabs, stage layout, device frame, OS chrome, edge materials, arch panel, AND re-declared DS components (`.avatar` l.58, `.kpi` l.68–72, `.card` l.73, `.meta` l.74).
- **Device frames separate? No.** Frame CSS lives in `app.css:27–41`, markup inline in `index.html:74–87`, geometry partially in `src/workspace/devices.js` (the only true single source — 9 lines, exemplary).
- **OS layers separate? No.** Status bar (`index.html:77`, `app.css:46–53`) hardcodes `9:41`, a fixed island (ignores `devices.js` `notch:` island/hole/notch/none), and a static battery; home indicator (`app.css:77–78`) sits beside the dock rules it must coordinate with.

Supporting findings: `DockSlices.jsx` (131), `DockLens.jsx` (116), `BottomDock.jsx` (107) exceed the 100-line rule; `GlassBars.jsx` mixes shell (`TopPills`) with in-device (`DeviceAppBar`); dead `.float-tabs`/`.stage` rules linger in `app.css:3–23`; `tests/` covers contrast/a11y only — `src/logic/*` and the morph pipeline have zero unit tests; AGENTS.md cites `scripts/map-graph.mjs` + `docs/graph.mmd` which do not exist; Architecture panel is a "coming next" placeholder.

## Target layer map (dependency rules)

```
index.html               mounts only (≤60 lines) — no styling, no logic
src/shell/               workspace chrome: controls, canvas viewport, launcher, slowmo
src/device/              frame + geometry — reads devices.js, owns radii/bezel/squircle
src/os/                  status-bar (live clock/battery), notch variants, home-indicator, edge materials
src/glass/               islands, split by scope: shell-scoped (pills) vs device-scoped (dock, appbar)
src/patterns/            app screens — vanilla, mount(page), no OS/device knowledge
src/logic/               pure state machines — zero DOM imports, unit-tested
src/components/          DS — gallery-proven, single source for avatar/card/kpi/meta
```

Rules: patterns → components/tokens only; glass → tokens + `app-tab` events; os/device/shell never import patterns; logic never touches DOM; geometry flows one way from `devices.js`.

## Cross-session rules (every phase)

- Ship rule: one concern-sized commit per task; DS-path commits carry `[plan:2026-09-22_122850-museum-refactor.md#phase-N]` on the SUBJECT line; run `npm run ds:track` + `npm test` before every commit; manifest commit last, then `git restore design-system/changelog-manifest.json`.
- Learning rule: every task ends with a Capture step per the protocol below — no task is done until its learning is routed. This is what makes best practice automatic: the agent reads AGENTS.md + the skill every session, so written rules are followed without being asked.
- Ports: user lives on :5173 — never kill it; agent verifies on :5174; static dist checks on 5199+.
- Baselines: `/tmp/museum-baseline/` persists across sessions; re-shoot only when intentional.
- Budget: `wc -l` ≤99 per file after every split (counter is `split('\n').length` — trailing newline counts).
- No push / no deploy without explicit `y`.

## Learning capture protocol — the project remembers

Why this works without asking: the agent loads `AGENTS.md` (repo law) and the `crm-app-prototype` skill (procedures) at the start of every session. Anything written there is obeyed by default. So every task's final step is:

**Capture step (every task):** ask "what did this task teach that the next task must not re-learn?" Route the answer:

| Learning applies to | Write it in | How |
| --- | --- | --- |
| Every future change (law, gate, budget, port, commit shape) | `AGENTS.md` new/augmented `§N` + mirror line in plan report | Append one bullet under the matching section; never rewrite existing law |
| Prototype look/procedure/pitfall (glass tune, frame geometry, verify recipe) | `crm-app-prototype` skill via `skill_manage` patch | One rule per lesson: imperative rule + why, no incident narration |
| One phase's context (why a split point was chosen) | `docs/decisions/NNN-<slug>.md` (created in Phase 1, Task 1) | 5 lines: context, options, decision, why, consequences |
| One-off, no reuse value | Task report only — do not file | Keeps the lawbooks lean |

Rules for the capture itself: one lesson = one bullet; imperative voice ("Keep X in … because Y"); file it in the same commit as the task (law/skill/decision rides with the code it governs); if two sessions disagree, newest entry wins and cites the superseded one — never silently contradict. Phase 9 verifies the ledger: every decision file linked, no dead rules (each cited by ≥1 module header).
