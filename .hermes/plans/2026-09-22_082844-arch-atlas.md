# Architecture Atlas Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Replace the static `#panel-architecture` doc with a self-improving Architecture Atlas — left-panel navigation (Logic / Components / IA / Flows) driving a high-craft right-hand SVG canvas that shows the product design's essence, and that gains resolution as the product is refined.

**Architecture:** A generated essence manifest (`scripts/generate-arch-atlas.mjs` → `src/arch/atlas.json`, manual overrides in `scripts/arch-atlas.manual.json`) rendered by a thin `src/arch/` layer (data → layout → SVG render → lens state); lenses are pure view filters over one model, never separate graphs.

**Tech Stack:** Vanilla JS + inline SVG (no canvas 2D, no new deps), Vite MPA, existing workspace canvas viewport + `devices.js` geometry gods, `ds-track`/`plan-names` gates.

**Tags:** Design System, Component, Layout, Function, Tooling

---

## Current context / assumptions

- Clicker `src/js/mechanics/` proved the interaction model (dual graph, orthogonal routing, pan/zoom, tooltips) but its bar is hobby: canvas 2D, every-function nodes, hand-placed coordinates, generated JS edited by hand.
- crm_proj already has the essence sources: `src/logic/funnel-machine.js` (Operate/Monitor states), `src/patterns/OperateScreen/*` + `OppsHome/opps-home.js` (Opportunity screen composition), `src/components/*` (29 DS components, gallery-proven), `DESIGN.md` + `tokens/primitives.json` (gems, signal, typography), `docs/graph.mmd` + `docs/flows/*.mmd` (module truth).
- Shell already exists: `index.html` `#panel-architecture > .ws-canvas--arch > .arch` static doc + `#ws-arch-stack` left note; workspace grid `300px | 1fr`, right panel full-height. This plan reuses that shell and does not touch the device/dock.
- Constraints (repo law): ≤100 lines per file (`wc -l` ≤99 with trailing newline), tokens only via `var(--token)`, layer contracts in `ARCHITECTURE.md`, plan trailer `[plan:<file>#<anchor>]` on DS-path commits, `npm test` green, `:5173` never killed, verify on `:5174`, no push without explicit `y`.

## Proposed approach

Model the **product idea**, not the code: 3 lenses over one manifest — (1) **Product Logic** (what governs Opportunity: funnel-machine states, transient vs temporal, tab bridge `app-tab`), (2) **Component Library** (which DS components each screen composes, with live usage counts), (3) **Information Architecture** (app → tabs → screens → overlays containment tree). Resolution ladder L1 essence → L2 contracts → L3 implementation; generator stamps staleness so the atlas visibly improves with each product change. SVG (not canvas) for typographic sharpness, a11y, and print-clean presentation stills.

## Risks, tradeoffs, open questions

- **Generator drift fatigue:** `--check` in `test` forces regen on every product edit; mitigated by one-command `npm run gen:atlas` + clear drift message naming the stale source.
- **Scope creep (full code graph):** explicitly out — essence only; `docs/graph.mmd` remains the code-truth outlet.
- **Open:** L2 contract extraction depth (props vs events only?) — default props+events, expand only on your approval; left-nav taxonomy (Logic/Components/IA/Flows vs Product/Design/System) — first cut ships former, rename is a copy-only change.
